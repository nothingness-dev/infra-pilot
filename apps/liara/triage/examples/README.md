# Sanitized OFFLINE MOCK examples

Every pair is synthetic, explicitly labeled by filename and `MOCK-service`.
Diagnosis pairs also carry `data_source=mock`. No real provider observations,
credentials, identities, approvals, or execution occurred.

All responses were serialized from existing Pydantic models or
`TypeAdapter(GateDecision)` after running the actual engine/gate. They are not
handcrafted result objects. The offline identity fixture uses one preinstalled
opaque session and narrowly scoped MOCK permissions; it is not HTTP authentication.

| Scenario | Request file | Response file | Interface |
| --- | --- | --- | --- |
| HTTP 500 + database connection failure | `mock_db_http500.request.json` | `mock_db_http500.response.json` | `POST /internal/triage/diagnose` |
| CPU 97% + latency 2400 ms | `mock_cpu_latency.request.json` | `mock_cpu_latency.response.json` | `POST /internal/triage/diagnose` |
| Healthy + incomplete observations | `mock_healthy_incomplete.request.json` | `mock_healthy_incomplete.response.json` | `POST /internal/triage/diagnose` |
| Sensitive restart pending approval | `mock_sensitive_pending.request.json` | `mock_sensitive_pending.response.json` | Trusted Python `ApprovalGate.request_approval` only; no HTTP route |
| Authorization denied without verified identity | `mock_authorization_denied.request.json` | `mock_authorization_denied.response.json` | Configured Python `ApprovalIntegration.authorize`; HTTP-shaped request |

The last denial uses a configured real gate and no authenticated identity,
producing `unauthenticated`. The default HTTP app instead returns 503
`approval_integration_unavailable` because no bridge/resolver is installed. Do not
misrepresent the offline example as a live default HTTP response.

All proposals remain `not_executed`. Pending approval has `allowed=false`, no
authorization ID, and no approving actor. Its fixed MOCK clock is 2026-01-01 UTC;
the stored request ID is genuinely generated by the gate and changes on regeneration.
It is a historical fixture, not a usable live approval or bearer credential.

To explicitly regenerate the known example JSON files offline:

```powershell
Set-Location -LiteralPath 'C:\git\shared\infra-pilot\apps\liara\triage'
.\.venv\Scripts\python.exe -m infrapilot_triage.example_payloads --mock
.\.venv\Scripts\python.exe -m pytest -p no:cacheprovider
```

The generator never starts a server, connects to Liara, grants approval, or
executes an action. It writes only these ten module-local JSON fixture files.
The test suite verifies diagnosis pairs against actual HTTP output, canonical
pending bindings, denial semantics, and the explicit MOCK opt-in.
